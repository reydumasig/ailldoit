# Ailldoit Codebase Audit

**Date:** 2026-04-19
**Auditor:** Claude (Cowork)
**Scope:** Full stack — backend, frontend, infra, docs
**Method:** Read all top-level md files for context, then parallel subagent audits of `server/`, `client/`, and deploy infra, plus `npm run check` + `npm run build` verification.

---

## TL;DR

Ailldoit is a working AI-powered social media ad generator — Firebase auth, Drizzle/Postgres, Gemini + Replicate + OpenAI integrations, Meta/TikTok/YouTube OAuth + real publishing, Cloud Run deployment. **The core product is functional end-to-end**, but prior audit docs (Jul 2025, Jan 2025) over-claim "100% production-ready" — current state is closer to **~80% production-ready** with several stale-code and operational gaps that should be fixed before the next deploy.

Severity scale used below: 🔴 blocker · 🟠 high · 🟡 medium · 🟢 low / polish

---

## ✅ What IS Working

### Backend (`server/`)
- **Auth:** Firebase JWT verification middleware on 53+ protected routes. Token flow solid.
- **Campaign CRUD:** Full `/api/campaigns` lifecycle (create, read, update, delete, generate, publish).
- **AI generation pipeline:**
  - Gemini text (`gemini-2.5-flash`), images (`imagen-4.0-ultra`), and Veo for video — all wired to real APIs.
  - Replicate SDXL as image fallback.
  - 4-tier image model fallback chain.
- **Publishing — real API integration** (not mocks): Meta Graph, TikTok, YouTube OAuth connect → token exchange → actual posting, with scheduled publishing.
- **Database schema:** 11 Drizzle tables (users, campaigns, assets, oauthConnections, creditUsage, learningPatterns, etc.) with proper FKs — clean.
- **Rate limiting:** Token-bucket limits per endpoint category (auth, text gen, image gen, video gen).
- **Stripe:** Webhook signature verified, dev/prod key switching via domain detection.
- **Long-video route:** `/api/campaigns/:id/generate-long-video` exists and stitches Veo clips via FFmpeg.

### Frontend (`client/`)
- **Auth flow:** Firebase email/password + Google OAuth → backend `/api/auth/verify`. Token auto-refresh + retry circuit breaker.
- **TanStack Query:** Used consistently; auth header auto-injected via `getAuthHeaders()`.
- **Pages functional:** dashboard, campaign-form, ai-generator, publishing, publishing-results, oauth-connections-enhanced, SuperAdminDashboard, login/register.
- **Real API wiring:** No mock-data pages — all screens hit the real backend.
- **OAuth UI:** Facebook SDK integration + backend-driven OAuth for TikTok/YouTube.

### Infra
- **TypeScript config:** Strict mode on, path aliases (`@/*`, `@shared/*`) consistent across tsconfig + Vite.
- **Vite dev proxy:** `/api` and `/videos` correctly proxied to Express on 8080.
- **Cloud Build pipeline:** `cloudbuild.yaml` builds image with Cloud Secrets injection → pushes to Artifact Registry → deploys to Cloud Run.
- **Dockerfile:** Multi-stage (builder → runtime), includes FFmpeg, production-only deps in runtime layer.
- **Stripe environment separation:** Dev/prod keys properly gated by domain detection.

## ❌ What is NOT Working / Broken / WIP

### 🔴 Blockers

1. **Local build fails on ARM64 (Apple Silicon).**
   - `npm run build` → `Cannot find module '@rollup/rollup-linux-arm64-gnu'`.
   - Dockerfile hard-codes `@rollup/rollup-linux-x64-musl` install (line 19) — fine for Cloud Build (x64), breaks local dev on M-series Macs.
   - Fix: install the platform-matching rollup native binary conditionally, or remove the `--force` manual install and let npm resolve.

2. **TypeCheck fails.**
   - `npm run check` reports a JSX-closing-tag error in `client/src/pages/campaign-form-old.tsx:225`.
   - This file is **not imported anywhere** — it's dead code. Deleting it makes typecheck pass.

3. **OAuth token refresh is unimplemented.**
   - `server/services/oauth-service.ts:263` throws `"Token refresh not implemented for platform: ..."`.
   - Meta/TikTok/YouTube tokens expire (hours to ~60 days). After expiry, **all publishing for that user will 401**. This is a silent time-bomb in production.

### 🟠 High

4. **Platform analytics endpoints are stubs.**
   - `publishing-service.ts:205–227` (`getMetaAnalytics`, `getTikTokAnalytics`, `getYouTubeAnalytics`) reference env vars `META_ACCESS_TOKEN`, `TIKTOK_ACCESS_TOKEN`, `YOUTUBE_ACCESS_TOKEN` that are **not in `.env.example`** and don't make sense as global vars (tokens are per-user in `oauthConnections`). Any call to analytics will 401.
   - Fix: read tokens from `oauthConnections` table per user, not process.env.

5. **"Long video" PR over-claims features.**
   - `PR_DESCRIPTION.md` lists: Scene Extension, Reference Images, Frame-Locking, Sub-Second Trimming via Veo 3.1 + Files API.
   - Backend subagent found **only FFmpeg stitching** — no scene extension, no frame-locking, no Files API upload in current code. Either the PR was reverted or never merged. Reality: generates N Veo clips and concatenates them.

6. **Cloud Run target service mismatch.**
   - `cloudbuild.yaml` deploys to `ailldoit-dev`.
   - `deploy-staging.sh` / `deploy-run.sh` / `deploy-feature-staging.sh` target `ailldoit-staging`.
   - Two deployment paths to different services — guaranteed drift/confusion.

7. **Admin gate is client-side only.**
   - `SuperAdminDashboard.tsx:82` hardcodes `['rey@ailldoit.com', 'rey@taxikel.com']` whitelist **in the React bundle**. Trivial to bypass by anyone who opens devtools — the sensitive `/api/admin/*` endpoints must enforce this server-side.
   - Also in `server/routes.ts:310–313`, an admin role check is commented out.

### 🟡 Medium

8. **OpenAI fallback disabled.** `ai-service.ts:52–94` is a fully commented-out OpenAI block. Only Gemini is active. Intentional? Undocumented if so.
9. **135 `console.log` calls** in client code (AuthContext, queryClient, firebase.ts, login.tsx, ai-generator.tsx, oauth-connections-enhanced.tsx). Debug noise in production.
10. **No DB migrations committed.** `drizzle.config.ts` points to `./migrations/` but the folder is empty. `db:push` does introspect-and-apply without a file trail — schema history is not auditable in git.
11. **Dead / duplicate pages:** `client/src/pages/campaign-form-old.tsx` (486 lines, unused), `oauth-connections.tsx` (superseded by `oauth-connections-enhanced.tsx`).
12. **Broken sidebar links:** `sidebar.tsx:33–34` links to `/analytics` and `/settings` — neither route exists in `App.tsx`.
13. **Unsafe URL parsing:** `ai-generator.tsx:41`, `publishing.tsx:34`, `publishing-results.tsx:48` extract campaign ID via `location.split("/")[2]`. Use Wouter's `useRoute()` params instead.
14. **ai-generator.tsx is 950 lines** — handles data fetch, video preview, export, variants, predictions. Needs decomposition.
15. **No error boundaries** anywhere in the React tree — a single render error blanks the app.
16. **Undocumented env var:** `VERTEX_API_KEY` is referenced in `deploy-staging.sh:65` but absent from `.env.example` and `.env.production.example`.
17. **`.env` copied into runtime container** (Dockerfile line 80) — Cloud Run secret injection would be safer than baking env into the image layer.
18. **`deploy-run.sh` uses `:latest` image tag** — no version pinning, risk of re-deploying stale images.
19. **Hardcoded defaults** in `publishing.tsx:36–42` (budget 500, audience "Teens 13-19 in Manila", 7 days) and `test-learning.tsx:22–34` (mock campaign ID "4").

### 🟢 Low / Polish

20. Committed artifacts at repo root: `veo2_1754400907657.mp4` (~1.8 MB), `temp/`, `dist/`, `test-long-video.js`, `test-migration.js`, `audit-campaign-91.sh`, `check-logs.sh`. Gitignore and clean up.
21. Browserslist data 9+ months stale (from July 2025 audit; almost certainly still stale).
22. `publishing-simulation.ts` mock service remains alongside real publishing service — fine for test, document clearly.
23. 4 uncommitted modifications: `client/src/lib/queryClient.ts`, `client/src/pages/campaign-form.tsx`, `server/routes.ts`, `server/services/ai-service.ts`. Several untracked md docs and deploy scripts.
24. Documentation drift: prior audits (`MVP_FEATURE_AUDIT_2025.md`, `PRODUCTION_READINESS_AUDIT_2025.md`) still claim "100% complete" and "95% ready" — these should either be archived or updated.

## 🔐 Security Summary

- ✅ No SQL injection surface (Drizzle parameterized throughout).
- ✅ JWT verified on protected routes; CORS headers intentional (`same-origin-allow-popups` for OAuth).
- ✅ Stripe webhook signature verified.
- ⚠️ Admin endpoints rely on client-side whitelist (#7). **Fix before the next deploy.**
- ⚠️ `.env` baked into Docker image (#17) — move to Cloud Run secret mounts.
- ⚠️ No rate limiting on webhook routes (acceptable; they're signature-verified).
